# Markdown 서식 보정 v1.1

기존 서식의 정보 책임을 유지하며 다음 사항만 보정한다.

| 필드 | 규칙 |
| --- | --- |
| `status` | 기존 열거형에 `unknown` 추가. 프로젝트 전체 상태를 확인하지 못한 경우 사용. 공개 화면에서는 상태 표시 생략 또는 미확인 표시; 완료나 출시로 변환하지 않음. |
| `participation` | 선택 문자열. 개인의 참여 시점 및 범위. 역할 및 프로젝트 상태와 구분. |
| `technologies` | 실제 확인된 엔진, 언어, API, 기술. 미확인 시 빈 배열 허용하되 과제의 기술 요구사항 검증은 미완료로 기록. |
| `implementation_techniques` | 선택 문자열 목록. 구현 기법 또는 기능 범주. 기술 스택과 구분하여 필요 시 표시. |
| `publication` | 선택 객체. `title`, `journal`, `publisher`, `year`, `month`, `volume`, `issue`, `pages`, `author_role`, `doi`. 논문 게재와 프로젝트 완료는 별개. DOI는 식별자로 관리하며 링크는 DOI에서 생성 가능. |
| `period` | 확인된 실제 시작·종료 시점만 기재. 미확인 시 생략. |

공통 섹션의 정보 책임을 유지하되 프로젝트 특성에 따라 제목을 조정할 수 있다. 예: 설계 중심 프로젝트의 `플레이 및 실행 구조 설계`.

개발 진행 여부, 성숙도, 공개 상태를 분리하는 전면적 스키마 재설계는 이번 국소 수정에 포함하지 않는다. 현재 `status`의 미확인 처리와 개인 참여 범위 분리만 적용한다. 외부 링크 존재 자체로 배포 또는 운영 여부를 확정하지 않는다.
