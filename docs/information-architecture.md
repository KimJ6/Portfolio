# 정보 구조 및 형식 설계 (저장소용 요약)

이 문서는 대화에서 확정한 정보 구조 및 형식 설계를 현재 구현에 맞춰 정리한 것이다. 상위 기준은 [요구사항 및 작성 원칙](requirements.md)이다.

## 정보 전달 단계

1. 메인: 작성자 식별 및 관심 분야, 자기소개, 대표 프로젝트 요약과 이력서 접근.
2. 상세: 프로젝트의 문제, 개인 역할, 판단, 수행 내용과 결과를 설명.
3. 검증: 소스 코드, 논문, 데모 및 설계 문서 링크 제공.

## 화면별 정보 책임

| 영역 | 정보 책임 |
| --- | --- |
| 헤더 및 푸터 | 주요 페이지와 GitHub, PDF 탐색 |
| 자기소개 | 정체성, 관심 분야, 개발 관점, 핵심 슬로건 |
| 대표 캐러셀 | 대표 프로젝트의 시각 자료, 상태 또는 참여 형태, 주요 결과, 상세 탐색 |
| 프로젝트 목록 | 전체 프로젝트의 문제, 기여, 결과, 기술 비교; 대표 캐러셀과 이미지 중복 최소화 |
| 상세 상단 | 프로젝트명, 유형, 상태, 역할, 기술, 개요, 주요 링크 및 이미지 |
| 상세 본문 | 문제 정의, 역할 및 기여, 설계 및 구현(특성에 따라 제목 조정), 결과 및 검증; 필요한 인사이트와 한계 |
| 관련 자료 | 검증 가능한 외부 자료 및 논문 서지 |
| 이력서 | 프로젝트 경험(각 설명 아래 사용 기술), 연구 성과 (독립 기술 역량 및 학력·어학 제외) |

## 원본 및 출력 책임

- `content/profile.md`: 공통 프로필과 헤드라인, 관심 분야, 링크.
- `content/projects/*.md`: 프로젝트별 메타데이터와 본문, 이미지 및 관련 자료 참조.
- `content/resume.md`: 이력서 출력 설정과 프로젝트 ID 참조. 공통 사실을 복제하지 않는다.
- `assets/`: 공개 가능한 이미지. `src/`: 표현 및 상호작용. `scripts/`: 검증 및 빌드. `site/`: 생성물.
- `docs/`: 관리 기준 및 작성 서식; 웹사이트 콘텐츠로 출력하지 않는다.

제목 계층은 메인 H1(슬로건), H2(프로젝트), H3(프로젝트명), 상세 H1(프로젝트명), H2(주요 섹션), H3~H4(사례)로 구성한다. 모바일에서도 정보의 순서와 의미를 유지한다. 문단마다 하나의 정보 책임을 부여하고 제목, 요약, 본문, 근거의 위계를 유지한다.

개발 및 기획, 연구, 기타 소프트웨어 프로젝트는 공통 상위 정보 책임을 유지하되 사례의 제목과 설명 깊이를 조절한다. 동일한 사실의 여러 출력은 허용하지만 여러 원본에서 독립 수정하지 않는다.

추가 경험 문서는 선택 사항이며 현재 빌드에서 구현하지 않았다.

## 프로젝트 표시 순서

기존 프로젝트의 상대적 순서를 유지하며, 사용자 요청에 따라 PinShift를 추가한 현재 순서는 렌더링 연구 → Drilling → OverTheHorizon → PinShift → PrecisionTick Metronome이다. 메인, 캐러셀, 상세 페이지의 다른 프로젝트 목록, 이력서에 동일한 `order`를 적용하며, 사용자 요청 없이 순서를 변경하지 않는다.
